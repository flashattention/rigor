## 2. 주요 결정 요약
- **제품**: 확률 대신 등급(0013), 직설 고정(0012), 지원자 편·B2B 금지(0015), 한국 거주자 대상

- **비용**: 월 실지출 상한 ₩10,000, 인프라 0원 목표, LLM은 Max 포함 크레딧($100/월)

# M1 계획 (승인 요청)

## 목표
CLI 하나로 **공고 + 이력서 + 공개 GitHub 저장소 → (A~F) → Markdown 리포트**가 끝까지 동작한다. 합성 평가셋으로 기준선 지표를 처음 측정한다.

## 범위 조정 제안: M1a / M1b로 나누기
ADR-0017과 ADR-0011로 M1 범위가 브리프 원안(1~2주)보다 커졌다. 한 번에 하면 약 4~5주다. 그래서 두 단계로 나눠 **2주 안에 끝까지 동작하는 버전**을 먼저 만든다.

| 단계 | 작업 | 예상(풀타임 기준) |
|---|---|---|
| **M1a-0** 골격 | `pyproject`(uv), ruff, pytest, GitHub Actions(테스트), Pydantic 스키마, `LLMClient`(Fake·녹화·OpenAI 어댑터), `routing.yaml`, `pricing.yaml`, 비용 확인 CLI, README 초안, LICENSE | 1~2일 |
| **M1a-1** 합성 데이터 생성기 | 정답을 먼저 정하는 템플릿 생성기: 프로필·공고·**로컬 git 저장소**(별칭 이메일 커밋, AI 공동 작성 트레일러, 심은 비밀값·PII, 의도적 불일치) | 2~3일 |
| **M1a-2** A 준비 | 텍스트·텍스트 PDF·DOCX 파싱, claim 추출, 공고 파싱, 신원 확인(CLI 프롬프트) | 2일 |
| **M1a-3** B·C | 링크 검증, 후보 추천(규칙), 신호 수집(GitHub API·로컬 저장소), 기여 분석, claim 검증(규칙 단계) | 3일 |
| **M1a-4** D·E·F | 정합 선택지(CLI), 면접 카드, 요건 판정, 등급 규칙, 진단, 저장소 판정·배치, 개선·신규 계획, 단순 검증, Markdown 리포트 | 3일 |
| **M1a 데모** | 합성 케이스 1건 끝까지 실행 + 첫 측정(정확도 일부, 지연·비용) | — |
| **M1b-1** 입력 형식 | HWPX → HWP 5.x 텍스트 추출 → OCR(Tesseract vs PaddleOCR 오류율 비교 후 결정) | 3~4일 |
| **M1b-2** 검색 | claim 검증에 BM25 근거 검색 추가 | 1~2일 |
| **M1b-3** 평가 | 평가 러너(정확도·안정성·아첨·인젝션), 반사실 공정성 v0, 기준선 보고서(`evals/reports/`), 면접 노트 갱신 | 2~3일 |

- **M1a: 약 2주**, **M1b: 약 1~2주**
- 이 기간은 하루 대부분을 쓸 수 있다는 가정이다. 실제 가용 시간에 맞춰 조정한다.

## LLM 사용 순서
- M1a 초반: Fake LLM으로 흐름을 만든다(0원). 실제 호출은 OpenAI 잔여 크레딧(약 $4)으로 파이프라인 확인만 한다.
- Max 결제(약 7일 후) 이후: Haiku 5.5로 전환한다. **공식 기준선은 Haiku로 측정**한다(ADR-0009).
- 평가 비용: B 표준형(약 ₩11,000)을 Max 크레딧에서 충당한다(`cost-estimate.md`).

## M1 완료 기준
- 합성 케이스에서 CLI가 A~F를 끝까지 실행하고 리포트를 낸다. HWP·스캔 PDF 입력 포함.
- 모든 테스트가 네트워크·실제 LLM 없이 통과한다.
- 기준선 보고서에 `metrics.md` §1의 M1 지표가 표본 수·모델·프롬프트 버전과 함께 기록된다.
- 게이트 지표(결격 recall, 비밀값·PII 탐지, 아첨 저항, 인젝션 방어, 반사실 등급 변동, 비추천 대안)의 첫 측정값이 나오고, 미달 항목은 원인과 함께 보고된다.
- 면접 노트에 핵심 로직 설명이 추가된다: 등급 규칙, claim 검증, 기여 귀속, 공정성 테스트.
