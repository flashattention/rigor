# M1b 계획 (개정: 2026-11-01)

> M1a 종료 후 "포트폴리오·제품 가치" 점검(면접관 시점)을 반영해 우선순위를 바꿨다.
> 원칙: 기능을 더 붙이기 전에 **본인 소유 증명**과 **외부 근거가 있는 숫자**를 먼저 확보한다.

## 확정 사항 (2026-11-01)
- 본인 데이터 실행: 사용자 동의함. 이력서는 `data/private/`(git 제외)에만 두고, 결과도 그 안에만 저장한다. LLM에는 마스킹된 텍스트만 전송된다 (현재 OpenAI, 이후 Anthropic).
- 분석 대상: GitHub `flashattention` 계정의 공개 저장소 (2026-11-01 기준 40개 이상, 포크 5개 포함).
- Max 포함 API 크레딧은 **다음 달(12월)에 새로 들어온다.** 그래서 2단계의 공식 Haiku 기준선은 12월에 잰다. 그 전에는 남은 OpenAI 크레딧(약 $3.98)으로 평가 러너를 완성하고, 잠정 수치만 낸다 (공식 기준선 아님).
- 지인 시험 사용(4단계)은 나중에 진행한다.
- 리뷰 방식: 핵심 모듈은 직접 리뷰(B), 나머지는 결과 보고(A).

## 다음에 이어갈 곳 (ADR-0020으로 개정)
- 재개 순서: 저장소 검증 에이전트 → 평가 → MCP 서버 → LangGraph 체크포인트·사용자 확인 → FastAPI+SSE·최소 화면 → 주요 업무 판정·근거 강도(Q29) → 매칭.
- 지금 할 일: 사용자가 `app/rigor/agent/loop.py`의 `verify_claim`을 직접 구현한다. `tests/agent/test_loop.py`가 명세다.
- RIGOR는 아직 어떤 이력서에도 없다. 사용자가 줄 단위로 설명할 수 있고 측정값이 나온 뒤에 넣는다.

## 소유 트랙 (1~5와 병행)
코드를 면접에서 설명할 수 있게 만드는 작업이다. 대상 모듈은 다섯이다.
- `agent/loop.py` (에이전트 루프, 직접 구현)
- `core/grading.py` (등급 규칙)
- `github_audit/claims.py` (claim 검증)
- `nodes/reconcile.py` (정합)
- `synth/` + 평가 러너 (평가 설계)

| 방식 | 내용 |
|---|---|
| 코드 읽기 | 모듈마다 10~15분. 이해가 안 되는 줄은 질문으로 남긴다 |
| 연습 과제 | `docs/interview-notes.md`의 과제 중 모듈당 1개 이상 **직접** 구현 (AI 도움 없이, 또는 도움 범위를 커밋 메시지에 정직하게 표시) |
| 확인 | 면접 노트의 예상 질문에 답을 직접 써 넣는다 |
