# M1b 계획 (개정: 2026-11-01)

> M1a 종료 후 "포트폴리오·제품 가치" 점검(면접관 시점)을 반영해 우선순위를 바꿨다.
> 원칙: 기능을 더 붙이기 전에 **본인 소유 증명**과 **외부 근거가 있는 숫자**를 먼저 확보한다.

## 확정 사항 (2026-11-01)
- 본인 데이터 실행: 사용자 동의함. 이력서는 `data/private/`(git 제외)에만 두고, 결과도 그 안에만 저장한다. LLM에는 마스킹된 텍스트만 전송된다 (현재 OpenAI, 이후 Anthropic).
- 분석 대상: GitHub `flashattention` 계정의 공개 저장소 (2026-11-01 기준 40개 이상, 포크 5개 포함).
- Max 포함 API 크레딧은 **다음 달(12월)에 새로 들어온다.** 그래서 2단계의 공식 Haiku 기준선은 12월에 잰다. 그 전에는 남은 OpenAI 크레딧(약 $3.98)으로 평가 러너를 완성하고, 잠정 수치만 낸다 (공식 기준선 아님).
- 지인 시험 사용(4단계)은 나중에 진행한다.
- 리뷰 방식: 핵심 모듈은 직접 리뷰(B), 나머지는 결과 보고(A).

## 왜 바꿨나
| 면접관이 찌를 약점 | 이번 계획의 대응 |
|---|---|
| "본인이 만들었나?" — 대부분 AI 공동 작성 | 소유 트랙: 핵심 모듈 4개 직접 리뷰 + 연습 과제 |
| "Agent라면서 에이전트가 어디 있나?" | 근거 탐색 에이전트를 규칙·검색과 비교하는 실험 (M2 → M1b로 당김) |
| "평가 점수가 무슨 의미인가?" — 자기 설계 합성 데이터 | 본인 실데이터로 써 보기 + 지인 3~5명 + 공개 저장소 |
| "쓰는 사람이 있나?" | 위와 같음, 항목별 "맞는 말/틀림" 집계 |

## 순서 (ADR-0018 반영)
| 단계 | 내용 | 비용 |
|---|---|---|
| **1. 본인 데이터로 써 보기** | 본인 이력서 + GitHub(`--github-login`)로 실행. 틀린 지적을 분류·합성 재현 회귀 테스트·수정 | 실행당 약 $0.005 |
| **1.5. 공고 출처 실측 + 매칭** | 공공 API의 IT 직군 커버리지 측정 후 매칭 경로 구현 (ADR-0019) | 0 (API) + 소액 |
| **2. FastAPI + Postgres 골격** | 실행 결과·감사 캐시·작업 큐 저장, SSE 진행 표시, LangGraph 그래프 + Postgres checkpointer(interrupt 후 재개) | 0 (로컬 Docker) |
| **3. 근거 탐색 실험** | 규칙 / BM25 / pgvector / 읽기 전용 도구 에이전트 비교 → 채택 결정, ADR-0010 결론 | 수백 원 |
| **4. MCP 서버 (로컬 stdio)** | 읽기 전용 도구 계층 하나로 내부 에이전트·외부 클라이언트 공유 | 0 |
| **5. 진단 상담 에이전트** | 리포트 조회·근거 검색·등급 시뮬레이터 도구. 압박 대화 등급 불변율 측정 | 소액 |
| **6. 평가 러너 + Haiku 기준선(12월) + README** | 정확도·안정성·아첨·인젝션·반사실 공정성, README 2분 이야기 | B안 (12월 크레딧) |
| (나중) 지인 3~5명 | 항목별 "맞는 말/틀림" 집계 | 소액 |

## 소유 트랙 (1~5와 병행)
코드를 면접에서 설명할 수 있게 만드는 작업이다. 대상 모듈은 넷이다.
- `core/grading.py` (등급 규칙)
- `github_audit/claims.py` (claim 검증)
- `nodes/reconcile.py` (정합)
- `synth/` + 평가 러너 (평가 설계)

| 방식 | 내용 |
|---|---|
| 코드 읽기 | 모듈마다 10~15분. 이해가 안 되는 줄은 질문으로 남긴다 |
| 연습 과제 | `docs/interview-notes.md`의 과제 중 모듈당 1개 이상 **직접** 구현 (AI 도움 없이, 또는 도움 범위를 커밋 메시지에 정직하게 표시) |
| 확인 | 면접 노트의 예상 질문에 답을 직접 써 넣는다 |

## 뒤로 미룬 것
HWP/HWPX·OCR 입력, 웹 배포 → M2 이후 (MCP는 ADR-0018로 M1b에 포함). 1~5에서 나온 실패가 이것들보다 우선이다.

## 완료 기준
- 본인 데이터 실행에서 나온 오류가 모두 분류·재현 테스트·수정(또는 "알려진 한계"로 명시)됐다.
- Haiku 기준선 보고서에 판정 안정성·아첨 저항·인젝션 방어·반사실 공정성 수치가 표본 수와 함께 있다.
- 에이전트 실험이 "채택/기각"을 수치로 결론 냈다.
- 외부 피드백(본인 + 지인)의 "맞는 말" 비율이 집계됐다.
- README만 읽어도 문제·검증·한계·숫자가 2분 안에 전달된다.
