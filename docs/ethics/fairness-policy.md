# 공정성 정책 (M0 초안)

> 상태: 초안. 승인 후 ADR로 승격하고, 요약을 서비스 화면("RIGOR가 보는 것과 보지 않는 것")에 공개한다.

## 1. 원칙
1. RIGOR는 **문서·요건·저장소**를 평가하며 사람을 평가하지 않는다.
2. 보호 속성은 매칭·진단·로드맵의 **입력 신호로 쓰지 않는다.** 가능하면 LLM에 아예 전달하지 않는다(구조적 차단 > 지시문 차단).
3. 공정성은 선언이 아니라 **자동 테스트로 측정**하고, 기준 초과 시 배포를 차단한다.

## 2. 사용하지 않는 정보와 차단 방법

| 정보 | 차단 방법 | 예외 |
|---|---|---|
| 이름 | LLM 전달 전 마스킹 토큰 치환 | 블라인드 노출 점검(규칙 기반, LLM 미사용) |
| 성별·성별 단서 | 추출 스키마에 필드 없음, 원문 마스킹 | 없음 |
| 나이·생년월일 | 추출 시 폐기 | 없음 (연차 요건은 경력 기간으로만 판단) |
| 사진 | 업로드 파일에서 이미지 추출 안 함 | 없음 |
| 출신 지역·주소 | 추출 시 폐기 | 근무지 요건은 사용자가 선호로 직접 입력한 값만 |
| **학교명·학교 서열** | 학력 fact는 `education_normalized`(학위·전공·상태)만 LLM에 전달 | 공고가 특정 학위·전공을 **명시적 요건**으로 둔 경우 그 충족 여부만 판단 |
| 병역 | 추출 시 폐기 | 없음 (병역 관련 요건은 `legal_check=flag`로 안내만) |
| 장애·건강 | 추출 시 폐기(민감정보) | 없음 |
| 가족·혼인·종교 | 추출 시 폐기 | 없음 |
| 국적 | 사용 안 함 | 공고의 근무 자격(비자) 요건은 사용자가 직접 답한 경우에만 |
| 경력 단절 기간 | 공백 자체를 약점으로 다루지 않음 | 공고의 연차 요건 계산에만 경력 기간 사용 |

**공고 쪽 보호 속성 요건**(예: "남성", "만 30세 이하", 특정 학교 우대): `legal_check=flag`로 판정에서 제외하고, 리포트에 "이 요건은 RIGOR 판정에 반영하지 않았다"고 안내한다. 공고의 위법 여부 판단은 하지 않는다.

## 3. 비전형 경로
- 비전공, 부트캠프, 독학, 해외 경력, 경력 단절, 이직은 **근거가 같으면 같은 판정**을 받아야 한다.
- 테스트: 근거 fact가 동일하고 경로 서술만 다른 쌍을 만들어 등급·요건 판정·어조 비교(`metrics.md` §3).
- 어조 가이드에서 "비전공자라서", "공백이 있어서" 같은 경로 기반 표현을 금지(Policy Checker 규칙).

## 4. AI 코딩 도구 사용과 기여도
- AI 도구 사용 여부는 **탐지하지 않는다**(신뢰할 수 있는 정적 탐지 방법이 없고, 오탐은 부당한 낙인이 된다).
- 사용자 자기 신고값은 감점에 쓰지 않고, 면접 준비(설계·검증 설명) 안내에만 쓴다.
- 커밋 비중은 판정 입력이 아니며, 항상 "불완전한 지표"라는 단서를 붙인다.

## 5. 반사실 공정성 테스트 (CI 게이트)
- 데이터: 합성 기준 프로필 N개 × 변형(이름 성별 단서 2종, 학교명 3종(서열 차이), 나이 단서 2종, 출신 지역 2종, 경로 서술 3종).
- 측정: 등급 변동률(게이트 0), 요건 판정 변동률(≤ 2% — 판정 안정성 기준선과 비교해 초과분만 위반으로 간주), 어조 점수 차이.
- 실행: 프롬프트·모델·그래프·루브릭 변경 PR마다 녹화 응답 + 소규모 실제 호출.
- 실패 시: merge 차단, `docs/failure-taxonomy.md`의 "공정성 위반" 유형으로 기록.

## 6. 공개
서비스 화면과 README에 "사용하는 정보 / 사용하지 않는 정보 / 테스트 결과(최근 실행일, 표본 수)"를 공개한다.

## 7. 열린 문제
- 학위 요건 자체가 간접 차별일 수 있다. RIGOR는 공고를 바꿀 수 없으므로 "공고 요건 충족 여부"만 사실대로 알리고, 대체 가능한 근거(동등 경력 인정 문구가 공고에 있으면)를 함께 표시한다.
- 영어 공고·영어 이력서에서 판정이 불리해지는지(언어 편향) 별도 측정 필요.
