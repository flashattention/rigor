# 규제 검토 초안 (M0)

> **법률 자문이 아니다.** 개발자가 공개 자료(대부분 해설 기사·블로그, 일부 정부 발표)를 읽고 정리한 검토 메모다. 조문 원문으로 확인하지 못한 항목은 "원문 확인 필요"로 표시했다. 서비스 공개(M3) 전에 원문 확인을 마치고, 가능하면 무료 법률 상담(예: 스타트업 지원 기관의 법률 자문 프로그램)으로 열린 질문을 확인한다.
> 작성 2026-11-01. 서비스 전제: 한국 거주 지원자 본인용 무료 베타(Q13), 기업 대상 기능 없음(ADR-0015).

## 1. 한국 AI 기본법

**알려진 사실** (보도·해설 기준)
- 2026-01-22에 시행됐다.
- 과기정통부는 과태료 계도기간을 최소 1년 이상 운영하고, 그동안 제재보다 안내에 집중한다고 밝혔다.
- 계도기간은 "과태료가 유예되는 기간"이지 의무가 유예되는 기간이 아니라는 해설이 있다(원문 확인 필요).
- 생성형 AI 제품·서비스를 제공할 때는 이용자에게 사전 고지해야 한다. 생성물 표시 의무도 있다.
- 투명성 사전고지 위반에 3천만 원 이하 과태료가 언급된다(시행령 입법예고 해설).

**RIGOR에 대한 판단**
- RIGOR는 LLM으로 진단문·로드맵·면접 준비 카드를 생성해 제공한다. 그래서 **생성형 AI 투명성 의무를 지킨다는 전제로 설계한다.** 이는 제품 원칙(브리프 §5.2)과도 같다.
  - 가입·첫 진단 전 화면: "RIGOR는 생성형 AI를 이용해 결과를 만듭니다" 고지
  - 모든 리포트·카드 상단: "AI가 생성한 결과" 표시
  - 이력서 업데이트안: "AI 생성 초안 — 사용자가 검토 후 사용" 표시
- **고영향 AI**: 법은 채용처럼 개인의 권리·의무에 중대한 영향을 주는 판단을 고영향 영역으로 다루는 것으로 알려져 있다(조문 원문 확인 필요). 고영향 판정 기준은 시행 당시 확정되지 않았다는 보도가 있다.
  - RIGOR는 기업이 지원자를 판단하는 시스템이 아니다. 지원자가 자기 서류를 점검하는 도구다. 채용 결정 권한을 가진 주체가 RIGOR 결과를 쓰지 않는다(ADR-0015).
  - 그래서 해당 가능성은 낮다고 보지만 **확정하지 않는다.**

## 2. 개인정보보호법

**처리하는 개인정보**: 이력서 텍스트(이름·연락처·학력·경력), GitHub 계정·저장소 데이터, 지원 결과(선택 동의), 서비스 이용 기록.

**민감정보는 수집하지 않는다**: 장애·건강 등은 추출 단계에서 폐기한다(ADR-0014).

| 항목 | 설계 반영 |
|---|---|
| 수집·이용 동의 | 필수 항목 최소화. 지원 결과 수집은 별도 선택 동의 |
| 만 14세 미만 | 가입 시 연령 확인으로 차단 |
| 최소 수집·파기 | 이력서 원본은 추출 후 즉시 삭제. 분석 캐시 90일. 계정 삭제 시 즉시 파기 |
| 안전성 확보조치 | 저장 암호화, 접근 권한 최소화, 접근 기록(감사 로그), 비밀값은 시크릿 매니저 |
| 처리위탁 | LLM 제공자, 트레이싱(Langfuse), DB(Neon), 클라우드(GCP)를 수탁자로 처리방침에 공개 |
| 개인정보 보호책임자 | 운영자. 표시 방식은 Q14(실명 표기 필요 여부 확인) |
| 유출 통지·신고 | 기한(72시간으로 알려짐, 원문 확인 필요)과 절차를 `docs/ops/runbook.md`에 둔다 |
| 정보주체 권리 | 열람·정정·삭제·처리정지 요청 경로, 데이터 내보내기 기능 |

**국외 이전**
- LLM 제공자와 일부 수탁자는 해외 사업자이거나 해외 리전이다. 법 제28조의8은 국외 이전을 몇 가지 근거가 있을 때만 허용한다. 근거는 정보주체의 별도 동의, 계약 이행을 위한 처리위탁·보관, 인증, 동등성 인정 등이다.
- "처리방침에 기재하는 것만으로 별도 동의를 대신할 수 없다"는 해설이 있다.
- **설계 결정(보수적)**: M3 동의 화면에 **국외 이전 별도 동의**를 둔다. 고지 항목은 이전 항목, 국가, 시기·방법, 이전받는 자, 목적, 보유 기간, 거부 방법과 효과다. 동의하지 않으면 서비스를 제공할 수 없다는 점도 알린다(LLM 없이 핵심 기능이 불가능하므로). 계약 이행 근거로 충분한지는 열린 질문으로 남긴다.
- **전송량 최소화**: 이름·연락처·학교명은 마스킹한 뒤 전송한다(`design.md` §6). 이렇게 해도 이력서 내용 자체는 개인정보이므로 국외 이전으로 본다.
- 확인할 것:
  - 각 수탁자의 데이터 보존 기간·학습 사용 여부·재위탁 구조
  - Max 포함 크레딧으로 호출하는 API의 데이터 정책이 일반 API와 같은지

## 3. EU AI Act
- 부속서 III의 고용 영역(채용·선발, 이력서 필터링, 후보 순위화)은 고위험으로 분류된다. 해설에 따르면 이 의무의 시행은 2026-08-02에서 2027-12-02로 연기됐다(출처 간 불일치 있음, 공식 관보 확인 필요).
- 이 조항들은 채용 의사결정에 쓰이는 시스템의 제공자·배포자(기업)를 겨냥한다. RIGOR는 ① 지원자 본인 도구이고 ② 한국 거주자 대상이다. 그래서 적용 가능성이 낮다.
- **대응**: 약관에 "한국 거주자 대상"을 명시하고 EU 대상 마케팅을 하지 않는다. 투명성 표시(§1)는 어차피 하므로 제50조의 취지도 충족한다.

## 4. 그 밖의 규정
- **채용절차법**: 구인자(기업)의 의무를 정한 법이라 RIGOR에는 해당하지 않는다. 블라인드 공고 노출 점검 기능은 지원자를 돕는 기능일 뿐 법적 의무 이행이 아니다.
- **공고 데이터**: 무단 크롤링은 부정경쟁행위·DB제작자 권리 침해로 인정된 판례가 있다. ADR-0005로 M3까지 사용자 붙여넣기만 쓰고, 사용자 간 공유를 금지한다. 상세는 `docs/data-sources.md`.
- **LLM 제공자 이용 정책**: 주요 LLM 제공자의 이용 정책은 고용 관련 사용 사례를 "개인에 대한 결정" 맥락에서 추가 요구사항(사람 검토, AI 사용 고지 등)이 있는 영역으로 다루는 것으로 알려져 있다(원문 확인 필요).
  - RIGOR는 개인에 대한 결정을 내리지 않는다. 그래도 고지와 사람 확인 단계(정합 선택, 결과 검토)는 이미 설계에 있다.
  - 조항 원문을 확인해 이 문서에 기록한다.
- **GitHub**: 공식 API만 쓴다. GitHub App 최소 권한, 요청 한도를 지킨다. 사용자 본인 저장소만 분석한다(ADR-0006).

## 5. 열린 질문
1. AI 기본법 고영향 판정 기준에서 "지원자 자기 점검 도구"가 제외되는지
2. AI 기본법상 RIGOR 같은 소규모·무료 서비스의 투명성 의무 이행 방식(고지 문구·위치)의 구체 기준
3. 국외 이전 근거로 "계약 이행을 위한 처리위탁"이 충분한지, 별도 동의가 필요한지
4. 개인정보 보호책임자 공개 시 실명 표기가 필수인지(Q14)
5. LLM 제공자 이용 정책의 고용 관련 조항이 지원자용 자기 점검 도구에 어떻게 적용되는지
6. Max 포함 API 크레딧 사용분에 일반 API와 같은 데이터 보존·학습 미사용 조건이 적용되는지
