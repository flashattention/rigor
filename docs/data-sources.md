## 저장 원칙 (M4에서 수집할 때)
- 레코드마다 기록한다: 출처, 수집 시각, 원문 링크, 약관 버전/확인일.
- 마감 공고는 매칭에서 제외하고, 정해진 기간 후 삭제한다.
- 출처 약관이 재게시를 제한하면 원문 대신 구조화 요건(우리가 추출한 필드)과 링크만 보여 준다.

## 직무 분류 체계 근거용 공고 분석 (taxonomy §5)
- 직무별 공개 공고 15개 이상을 **읽고 집계만** 한다. 원문은 저장소에 커밋하지 않는다. 남기는 것은 빈도표와 출처 URL이다.
- 수집 자동화 없이 수동으로 읽는다(크롤링 아님).

## 해야 할 일 (M4 전)
1. 공공 API 2종 활용신청 → 이용허락범위 확인 → IT 직군 커버리지 실측(목표 직무 공고 중 몇 %가 있는지)
2. 민간 API·ATS 약관 원문 확인 후 이 표 갱신
