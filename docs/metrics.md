# 지표 정의서 (M0 초안)

> 각 지표: 정의 · 계산 · 데이터 출처 · 목표/게이트 · 시작 마일스톤. "게이트" = CI에서 merge·배포를 차단하는 기준.
> 목표 수치는 기준선 측정(M1) 전 **가설**이며, 기준선 측정 후 이 문서에서 확정한다. 게이트 기준은 확정 전까지 "기준선 대비 악화 금지"로 운용한다.

## 0. 평가 데이터 원칙 (2026-11-01 결정)
외부 전문가 라벨러를 쓰지 않고, 사용자가 평가셋을 만들거나 정답을 매기지도 않는다. 정답은 아래 세 가지에서만 나온다.

| 정답의 출처 | 무엇을 | 예 |
|---|---|---|
| **구성상 정답** (합성 데이터) | 정답을 먼저 정하고 그에 맞게 코드로 데이터를 생성한다. LLM의 의견이 정답이 되지 않는다 | "r_3은 미충족"으로 설계한 프로필, 비밀값을 심은 저장소, LangGraph를 안 쓰는데 이력서엔 썼다고 적은 쌍 |
| **결정론 사실** | 코드로 확인 가능한 사실 | 테스트 디렉터리 존재, CI 설정 존재 |
| **실사용자 신호** (M3+) | 항목별 "맞는 말 / 틀림" 피드백, "사실과 다름" 신고, 지원 결과 | 베타 운영 데이터 |

**측정할 수 없는 것 (README에 공개)**: "진단이 현직자 시선으로 타당한가", "로드맵이 실제로 유용한가" 같은 주관적 타당성은 실사용자 피드백이 쌓이기 전까지 **미검증**으로 표시한다. LLM 판정기를 이 빈자리에 쓰지 않는다(§1.5).

공개 저장소(Q9)는 정답 라벨 없이 **견고성 테스트**에만 쓴다: 파서·분석기가 실패 없이 도는지, 저장소당 비용·지연은 얼마인지.

### 1.5 LLM-as-judge 운용 규칙
- 판정기는 **구성상 정답이 있는 합성 케이스로 먼저 정확도를 측정**한 뒤, 그 정확도가 확인된 항목에만 쓴다. 정답 자체가 없는 주관 항목에는 쓰지 않는다. 불가피하게 쓰면 결과에 "미검증 판정기"라고 표시한다.
- pairwise 비교는 A/B 순서를 바꿔 2회 판정, 불일치는 "동률" 처리.
- 판정기 모델은 피평가 모델과 다른 모델(또는 다른 버전)을 쓰고 이를 기록.

## 2. 비즈니스 지표

### 2.1 North Star — WVI (ADR-0007)
**주간 검증된 개선 사용자 수**: 지난 7일간 Improvement 또는 RoadmapItem 1개 이상이 재감사의 `DoneCriterion`으로 완료 확인된 고유 사용자 수.

### 2.2 퍼널 (이벤트 기반, 단계별 전환율)

|---|---|---|

| 가입 | `signed_up` | |

### 2.3 리텐션·가치
| 지표 | 정의 | 주의 |
|---|---|---|
| 주간 코호트 리텐션 | 가입 주 기준 N주차 활성 비율 | 채용 시즌 표시와 함께 해석 |
| 진단 "맞는 말" 비율 | 항목별 피드백 중 "맞는 말" / (맞는 말 + 틀림) | **아첨 유도 위험** → 아첨 저항률과 함께 본다 |
| "틀림" 신고 처리 | 신고 → 평가셋 후보 등록 비율, 처리 기한 준수율 | |
| NPS / CSAT | 진단 후 설문 | 표본 수와 함께 보고 |
| 결과 회수율 | `outcome_logged` / `application_logged` (지원 후 6주 기준) | 낮으면 합격률 추정이 상향 편향 |
| 등급별 서류 합격률 | 등급별 pass / (pass+fail) + 95% 신뢰구간 + 표본 수 | 등급당 표본 ≥ 약 160 전에는 "탐색적"으로만 표시 (`brief-review.md` §3.3) |
