# 작은 기술 선택 기록

> 큰 선택은 `docs/adr/`. 여기는 라이브러리·도구 수준의 선택을 한두 줄 이유와 함께 남긴다.

| 날짜 | 선택 | 이유 | 대안 |
|---|---|---|---|
| 2026-11-01 | **uv** (패키지·가상환경) | 빠르고, 잠금 파일(`uv.lock`)로 CI와 로컬 환경이 같아진다. 도구 하나로 Python 버전까지 관리 | pip+venv, Poetry |
| 2026-11-01 | **hatchling** (빌드) | 설정이 짧고, `app/rigor` 경로를 패키지로 지정하기 쉽다 | setuptools |
| 2026-11-01 | **Pydantic v2** (스키마) | API(FastAPI)·워커·LLM 출력 검증이 같은 모델을 공유한다 (ADR-0001) | dataclasses + 수동 검증 |
| 2026-11-01 | **PyYAML** (설정) | 라우팅·단가·루브릭 설정을 사람이 읽기 쉬운 형식으로. `safe_load`만 사용 | TOML |
| 2026-11-01 | **Typer** (CLI) | 타입 힌트로 옵션 정의, 테스트용 러너 내장 | argparse, click |
| 2026-11-01 | **pytest**, **ruff** | 사실상 표준. ruff는 린트와 포맷을 한 도구로 | flake8+black |
| 2026-11-01 | 제공자 SDK(`openai`, `anthropic`)는 **선택 의존성** | 테스트·fake 프로필은 SDK 없이 돈다. 어댑터는 실제로 쓸 때만 import | 필수 의존성 |
| 2026-11-01 | 구조화 출력은 **Pydantic으로 최종 검증** (제공자 strict 모드에 의존하지 않음) | 제공자마다 strict 스키마 제약이 달라 교체 비용이 커진다. 검증 실패 시 오류를 붙여 1회 재요청 | 제공자 strict 모드 |
