# ADR-0007: North Star Metric

- 상태: 제안됨
- 날짜: 2026-11-01
- 관련: `docs/metrics.md` §2, `docs/brief-review.md` §3

## 배경
NSM은 ① 사용자가 얻는 핵심 가치를 반영하고 ② 팀(1인)이 주 단위로 움직일 수 있고 ③ 측정이 객관적이고 ④ 늦게 오지 않아야 한다. RIGOR의 핵심 가치는 "솔직한 진단을 받고 **실제로 고쳐서** 지원 준비도가 올라가는 것"이다.

## 검토한 선택지

| 후보 | 가치 반영 | 측정 객관성 | 지연 | 조작·왜곡 위험 | 1인 규모에서 신호 |
|---|---|---|---|---|---|
| A. 진단 완료 수 | 낮음(사용량일 뿐) | 높음 | 즉시 | 높음(반복 실행) | 큼 |
| B. 추천 공고에 지원해 서류 결과를 받은 사용자 수 | 중간 | 자기 보고 | 2~6주 | 회수율 편향 | **매우 작음** |
| C. 진단 후 서류 합격률 개선 | 높음(이상적) | 인과 식별 불가 | 수주~수개월 | 선택 편향 | 통계 불가 |
| D. 진단 "맞는 말" 비율 | 중간(신뢰) | 자기 보고 | 즉시 | 아첨 유도 위험(듣기 좋은 진단이 점수↑) | 중간 |
| **E. 주간 검증된 개선 사용자 수 (WVI)** | 높음 — 고쳤다는 행동 | **GitHub 재감사로 객관 확인** | 1~3주 | 낮음(실제 저장소 변화 필요) | 중간 |

**E 정의(초안)**: 지난 7일 동안 *로드맵 항목 또는 저장소 보완 항목 중 1개 이상이 재감사로 완료 확인된* 고유 사용자 수.
- "완료 확인" = 해당 항목의 검증 가능한 완료 기준(예: 테스트 디렉터리와 CI 통과 배지 존재, README에 평가 결과 표 존재, 비밀값 제거)이 재감사의 결정론 신호로 충족됨.
- 이력서 표현 수정만으로 끝나는 항목은 제외(객관 확인 불가).

## 결정 (제안)
**E. 주간 검증된 개선 사용자 수(Weekly Verified Improvers, WVI)**를 NSM으로 한다.

보조(입력) 지표: 첫 진단 완료율 → 로드맵 수락률 → 항목 착수율(재감사 요청) → 항목 완료율.
**반대 지표(guardrail)**: 진단 "맞는 말" 비율(신뢰 하락 감시), 근거 없는 지적 비율, 공정성 테스트 위반 0, 사용자당 원가.
장기 결과 지표(NSM 아님): 서류 결과 회수율, 등급별 서류 합격률 — 보정용.

## 이유
1. 핵심 흐름 ②(프로젝트 선택·개선)의 가치가 **행동으로 실현되었는지**를 측정한다.
2. GitHub 재감사라는 **이 제품만의 객관 측정 수단**을 활용한다 — 자기 보고 의존을 줄인다.
3. 아첨으로 올릴 수 없다. 듣기 좋은 진단은 D를 올릴 수 있지만 E는 실제 저장소 변화가 있어야 오른다.

## 결과·트레이드오프 (포기한 것)
- 저장소 개선은 "합격"이 아니다. 개선이 합격 가능성을 높인다는 가정은 검증 대상으로 남는다(장기 결과 지표로 추적, 인과 해석 한계 명시).
- 로드맵이 신규 프로젝트 위주이면 완료까지 몇 주가 걸려 주간 값이 작다 → 작은 단위 항목(README 결과 표 추가 등)을 로드맵에 섞도록 Project Planner가 우선순위를 둔다. **단, NSM을 올리기 위해 쉬운 항목만 추천하는 왜곡을 막기 위해** 추천 항목의 근거 요건 인용과 현직자 유용성 평가를 guardrail로 둔다.
- 비GitHub 직군 사용자에게는 적용이 어렵다(현재 타깃 밖).

## 재검토 조건
- 베타 4주 후 WVI가 사용자 행동을 반영하지 못한다고 판단될 때(예: 인터뷰에서 가치 체감과 무관).
- 결과 데이터가 충분해져(등급당 수백 건) 합격률 기반 지표가 통계적으로 의미를 가질 때.
