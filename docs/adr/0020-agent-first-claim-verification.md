# ADR-0020: 저장소 검증 에이전트를 중심으로 재설계

- 상태: 채택됨 (2026-11-01)
- 날짜: 2026-11-01
- 관련: ADR-0006, 0008, 0010, 0017, 0018, 0019, `docs/failure-taxonomy.md`

## 배경
지금 RIGOR는 다음 단계를 코드가 정하는 워크플로이고, LLM이 다음 행동을 고르는 곳이 없다. Agent Engineer 포트폴리오로는 약점이다. 한편 실제 이력서 실행에서 규칙이 판단하지 못한 주장이 21개 남았다. 어느 파일을 열어야 할지 미리 알 수 없는 문제이므로, 에이전트가 필요한 자리가 데이터로 확인됐다.

## 결정 1: 순서

| 기준 | **에이전트 먼저** | 매칭 먼저 (ADR-0019 당시 계획) |
|---|---|---|
| 포트폴리오 가치 | 면접의 중심 주제 | 추천 시스템 요소 |
| 불확실성 | 문제가 데이터로 확인됨 | 공공 API의 IT 공고 커버리지 미확인 |
| 비용 | 실험 전체 $1 안쪽 (추정) | API 무료, 공고 DB 운영 부담 |
| 사용자 가치 | 판단 못 한 주장을 줄임 | 공고 탐색 |

**결정**: 에이전트 루프 → 평가 → MCP 서버 → LangGraph 체크포인트와 사용자 확인 → FastAPI + SSE와 최소 화면 → 매칭. 두 진입 경로라는 제품 방향(ADR-0019)은 유지하고 순서만 바꾼다.

## 결정 2: 코드를 실행하지 않는다

| 기준 | **읽기 전용 도구** | 샌드박스에서 테스트 실행 |
|---|---|---|
| 제품 원칙 | 준수 | "코드는 절대 실행하지 않는다"와 충돌 |
| 보안 | 인젝션을 당해도 읽기뿐 | 인젝션과 실행 권한이 결합, 격리 실패 시 피해 큼 |
| 검증력 | 구현 존재 확인에 충분 | 동작 확인은 강하지만 환경 문제로 자주 실패 |
| 비용·운영 | 0 | 컨테이너 실행 비용, 의존성 설치 시간 |

**결정**: 도구는 `tree`, `read_file`, `grep`, `git_log`, 그리고 종료 행동 `submit_verdict`뿐이다. Docker는 clone과 파일 파싱 격리에 쓴다.

## 결정 3: 규칙 먼저, 남는 것만 에이전트
규칙으로 확신할 수 있는 주장에 LLM을 쓰지 않는다. 규칙이 보류한 주장에만 에이전트를 쓰고, 등급은 계속 규칙이 계산한다(ADR-0008). 에이전트는 주장 하나의 판정만 낸다.

## 결정 4: 에이전트의 출력은 코드가 검증한다
저장소 내용은 신뢰할 수 없는 입력이고, 에이전트는 조종당하거나 근거를 지어낼 수 있다.
- "확인됨"·"근거와 다름"은 파일, 줄, 인용문이 필요하다. 인용문이 **에이전트가 실제로 연 파일의 그 줄 근처에 있어야** 인정한다. 아니면 "확인 불가"로 낮춘다.
- "근거 없음"은 읽을 수 있는 파일을 전부 살폈을 때만 인정한다. 일부만 봤으면 "확인 불가"다.
- 도구 결과는 데이터 블록으로 전달하고, LLM에 보내기 전에 비밀값과 사용자 식별 정보를 가린다. 커밋 작성자는 이름·이메일 대신 본인/타인만 표시한다.
- 경로는 저장소 스냅샷에 있는 것만 연다. 검색어는 정규식이 아니라 문자열로 다룬다.

## 결정 5: 평가
- 실제 공개 저장소에 참·거짓 주장을 붙여 정답을 만든다. 합성 저장소만으로는 부족하다는 것을 이미 확인했다 (18/18 뒤 실제 데이터에서 오류 십여 건). Q9를 이 범위로 개정한다: 저장소에는 URL과 커밋 해시만 남기고, 코드를 복사하지 않으며, 저장소 이름을 공개하지 않고, 삭제 요청 시 제외한다.
- 조정용과 최종 측정용을 나눈다. 최종 세트는 한 번만 잰다.
- 규칙 / 키워드 검색 / 에이전트의 재현율, **정밀도**, 비용, 지연을 비교한다. 사실을 거짓으로 지적하는 오탐이 가장 해로우므로 정밀도를 함께 낸다. 인젝션 방어율도 잰다.
- 에이전트가 이기지 못하면 그 결과를 그대로 공개하고 채택하지 않는다.

## 결정 6: 사용자가 직접 구현하는 부분
에이전트 루프와 MCP 서버는 사용자가 직접 작성한다. 면접에서 가장 깊게 묻는 부분이기 때문이다. 도구 계층, 인용 검증, LLM 어댑터, 테스트는 AI가 만들어 인터페이스를 고정한다. RIGOR는 아직 어떤 이력서에도 없으므로, 사용자가 줄 단위로 설명할 수 있고 측정값이 나온 뒤에 이력서에 넣는다.

## 결과·트레이드오프 (포기한 것)
- 매칭이 다시 늦어진다. 그동안 "어디에 지원할지"는 방향 전환 제안으로만 대응한다.
- 코드를 실행하지 않으므로 "구현이 실제로 동작하는지"는 확인하지 못한다. 리포트에 이 한계를 밝힌다.
- 다중 턴 호출이라 주장당 비용이 단일 호출보다 크다. 약 $0.007로 추정한다 (`gpt-5-mini`, 단가 미검증). 실측 후 고친다.

## 재검토 조건
- 비교 실험에서 에이전트가 키워드 검색 대비 의미 있는 개선을 보이지 못할 때.
- 동작 검증이 꼭 필요하다는 근거가 쌓일 때 → 격리와 권한을 다룬 새 ADR.

## 측정 결과 (2026-11-01, 잠정)
측정용 세트에서 채택 기준 3개 중 "참 주장 확인율이 키워드보다 높다"를 충족하지 못했다 (11/18 동률). 결정 5에 따라 에이전트를 채택하지 않고 결과를 공개한다 (`evals/reports/agent-test-2026-11-01.md`). 오탐률은 에이전트 0/18, 키워드 6/18이었다. 사람의 표본 확인 전이다. 후속 방향은 아직 정하지 않았다.
