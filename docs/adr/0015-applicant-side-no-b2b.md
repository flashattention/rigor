# ADR-0015: 지원자 편 원칙 — B2B 채용 평가와 유료 노출 금지

- 상태: 채택됨 (2026-11-01) — 브리프 §1.4·§4.3·CLAUDE.md 제품 원칙을 ADR로 명문화
- 날짜: 2026-11-01
- 관련: ADR-0006(본인 계정만 분석), `docs/brief-review.md` §4.3, 위험 R14·R23

## 배경
RIGOR의 기술(이력서 진단, GitHub 감사)은 기업이 지원자를 걸러내는 데에도 쓸 수 있다. 수익 면에서는 B2B가 더 쉬워 보일 수 있다. 하지만 그렇게 되면 다음이 동시에 바뀐다.
- **규제**: 채용 판단에 쓰이는 AI는 한국 AI 기본법의 고영향 영역, EU AI Act의 고위험 영역에 해당할 가능성이 높다.
- **윤리**: 지원자를 위한 도구가 지원자를 감시하는 도구가 된다.
- **신뢰**: 사용자가 이력서와 저장소를 맡길 이유가 사라진다.

## 검토한 선택지

| 기준 | A. 처음부터 B2B 병행 | B. 나중에 열어 둠(정책 없음) | **C. 금지를 명문화, 바꾸려면 새 ADR** |
|---|---|---|---|
| 규제 부담 | 높음 | 불확실 | 낮음 |
| 사용자 신뢰 | 낮음 | 중간 | 높음 |
| 수익 기회 | 있음 | 있음 | 포기(지원자 대상 모델만) |

## 결정
C. 아래를 하지 않는다.
1. 기업·채용 담당자에게 지원자 평가·순위·GitHub 분석을 제공하는 기능.
2. 사용자 본인이 아닌 사람의 GitHub 분석. 분석 대상은 GitHub App 인증 사용자 본인으로 강제한다(ADR-0006).
3. 기업에게 돈을 받고 특정 공고를 상위에 노출하는 것. 광고·제휴 공고를 도입하게 되면 반드시 표시하고 순위 산정과 분리하며, 별도 ADR을 쓴다.
4. 사용자 데이터를 기업에 제공·판매하는 것.

약관에 "타인의 이력서를 평가하는 용도로 사용 금지"를 명시하고, 이상 사용 패턴(짧은 기간에 서로 다른 사람의 이력서 다수)을 탐지한다.

## 이유
- 규제 대상이 될 가능성을 낮추면 1인 운영이 가능한 범위에 머문다.
- "지원자 편"이라는 위치가 차별점이자 사용자 신뢰의 근거다.

## 결과·트레이드오프 (포기한 것)
- B2B 수익 기회를 포기한다. 수익 모델 가설은 지원자 대상(프리미엄, 교육기관 단체 라이선스)으로만 검증한다. 교육기관 라이선스도 "기관이 수강생을 평가하는 용도"가 되지 않도록 조건을 둔다.
- 이력서 소유자를 기술적으로 확인할 수는 없다. 약관과 이상 탐지로만 대응한다.

## 재검토 조건
- 이 원칙을 바꾸려면 규제 검토와 위험 등록부 재평가를 포함한 새 ADR이 필요하다.
