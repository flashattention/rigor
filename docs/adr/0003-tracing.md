# ADR-0003: LLM 트레이싱 도구

- 상태: 제안됨 (브리프상 최종 선택은 사용자)
- 날짜: 2026-11-01
- 관련: ADR-0002, `docs/brief-review.md` §4.2

## 배경
노드별 입출력·토큰·비용·지연·재시도·interrupt를 추적해야 한다. 문제는 **trace에 이력서·비공개 코드 발췌가 그대로 담긴다**는 점이다. 따라서 기능보다 ① 개인정보 마스킹 ② 데이터 위치(자체 호스팅 가능 여부) ③ 평가 데이터셋 연계가 선택 기준이다.

## 검토한 선택지

| 기준 | LangSmith | Langfuse | Arize Phoenix | OpenTelemetry + 범용 백엔드 |
|---|---|---|---|---|
| LangGraph 연동 | 최상(같은 회사) | 공식 콜백·OTel | OTel/OpenInference | 직접 계측 |
| 자체 호스팅 | 엔터프라이즈 플랜 | **오픈소스, 자체 호스팅 가능** | 오픈소스 | 가능 |
| 관리형 무료 티어 | 있음 | 있음 | 있음(클라우드) | 백엔드별 |
| 마스킹 훅 | 있음 | 있음(mask 함수) | 직접 | 직접 |
| 데이터셋·평가 | 강함 | 있음(데이터셋, 점수, 프롬프트 관리) | 평가 강함 | 없음 |
| 벤더 종속 | LangChain 생태계 | 낮음(OTel 호환) | 낮음 | 없음 |
| 운영 부담 | 없음 | 관리형 없음 / 자체 호스팅 시 큼 | 관리형 없음 / 자체 호스팅 시 중간 | 큼 |

(가격·한도는 자주 바뀌므로 결정 시점에 공식 페이지로 확인해 이 ADR에 기록한다.)

## 결정 (제안)
**Langfuse 관리형(클라우드)으로 시작**하고, 마스킹 함수를 trace 전송 전에 반드시 통과시킨다. 실사용자 데이터가 쌓이는 M3 이후 데이터 위치 요구가 생기면 자체 호스팅으로 전환할 수 있다는 점을 선택 이유로 둔다.

## 이유
1. 오픈소스·자체 호스팅 경로가 있어 **개인정보 리스크가 커져도 도구를 바꾸지 않고 대응**할 수 있다.
2. OTel 호환으로 벤더 종속이 낮다.
3. 데이터셋·점수 기능으로 "프로덕션 trace → 평가셋 후보" 루프(브리프 §6)를 구현할 수 있다.

## 결과·트레이드오프 (포기한 것)
- LangSmith의 LangGraph 전용 디버깅 경험(그래프 단계 시각화 등)을 일부 포기한다.
- 관리형 사용 시 trace가 해외 서버에 저장 → **마스킹 필수**, 처리방침에 수탁자로 고지. 마스킹 누락 테스트를 CI에 둔다(합성 PII가 trace payload에 남는지 검사).

## 재검토 조건
- LangSmith가 동등한 자체 호스팅·마스킹 조건을 1인 개발 규모 비용으로 제공할 때.
- 관리형 무료 한도 초과로 비용이 월 예산의 20%를 넘을 때.
