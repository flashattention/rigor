# ADR-0012: 진단 어조를 직설로 고정

- 상태: 채택됨 (2026-11-01)
- 날짜: 2026-11-01
- 관련: `docs/rubric.md` §5, 브리프 §5.3·§4.4, 위험 R13

## 배경
브리프 원안(§5.3)은 사용자가 진단 강도(직설/완곡)를 고르게 하고, 어느 쪽이든 판정은 바꾸지 않게 했다. 그 목적은 직설적 진단이 줄 수 있는 상처를 줄이는 것이었다. 기본값을 묻는 질문(Q16)에 사용자가 "직설로 고정하면 안 되나"라고 제안했다.

## 검토한 선택지

| 기준 | A. 직설/완곡 선택 (원안) | **B. 직설 고정** |
|---|---|---|
| 제품 정체성 ("솔직한 피드백") | 완곡 모드가 정체성을 흐릴 수 있다 | 일관됨 |
| 사용자 보호 | 선택권으로 보호 | 어조 가이드 규칙으로 보호(아래) |
| 평가·테스트 부담 | 어조마다 공정성·어조·아첨 테스트가 필요하다 → 평가 실행 2배 | 1벌 |
| 비용 | 평가 LLM 호출 2배 | 절반 |
| 아첨 위험 | 완곡 모드에서 갭을 흐리게 쓰는 형태의 "말투 아첨"이 생길 수 있다 | 감시 지점이 하나 |
| 구현 | 프롬프트 2벌 + UI 선택 | 1벌 |

## 결정
B. 진단 어조는 직설 하나로 고정한다. 사용자 보호는 선택권이 아니라 **어조 규칙**으로 보장한다(`rubric.md` §5).
- 문서·요건·저장소에 대해서만 말한다. 인격·배경·보호 속성은 언급하지 않는다.
- 모든 지적에 근거를 단다. "비추천"에는 반드시 대안 경로를 붙인다.
- 지적만 나열하지 않고, 각 갭에 다음 행동(보완 방법)을 함께 준다.
- 고통 신호가 보이면 판정을 반복해 밀어붙이지 않는다는 가이드라인은 유지한다.

## 이유 (사용자 승인 사유 포함)
1. "솔직한 피드백"이 이 서비스가 존재하는 이유다. 완곡 모드는 그 차별점을 스스로 약하게 만든다.
2. 직설이 주는 상처는 대부분 사람을 평가하는 말투에서 나온다. 문서와 요건만 말하는 규칙이 그 원인을 직접 막는다.
3. 평가와 프롬프트를 한 벌로 줄이면 비용 원칙(월 ₩10,000)과 1인 개발 범위에 맞는다.

## 결과·트레이드오프 (포기한 것)
- 완곡한 표현을 원하는 사용자는 이탈할 수 있다. 베타의 항목별 피드백과 인터뷰에서 "어조 때문에 불편했다"는 신호를 따로 집계한다.
- 브리프 §4.4의 실험 예시(직설 vs 완곡 A/B)가 사라진다.

## 재검토 조건
- 베타에서 어조 관련 불만이나 이탈이 반복해서 관찰될 때. 이때는 선택권보다 먼저 어조 규칙을 고친다.
