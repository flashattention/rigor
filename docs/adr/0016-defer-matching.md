# ADR-0016: 매칭(공고 추천) 기능을 M4 이후로 이연

- 상태: 대체됨 (→ ADR-0019, 2026-11-01)
- 날짜: 2026-11-01
- 관련: ADR-0005(공고 수집), ADR-0010(벡터 DB), `docs/brief-review.md` §6

## 배경
브리프 원안은 M2에 매칭(Candidate Retrieval + Reranker)을 넣었다. 그런데 매칭에는 핵심 흐름에 없는 세 가지가 필요하다.
- 공고 DB와 그 수집의 합법성(ADR-0005)
- 대규모 검색 인프라(ADR-0010)
- 순위 평가 데이터

1인 개발에서 이것까지 M2에 하면 핵심 흐름(공고 1개 + 이력서 + GitHub → 적합도 + 프로젝트 선택·개선)의 품질이 희생된다.

## 검토한 선택지

| 기준 | A. 원안대로 M2 | **B. M4 이후** | C. 범위 밖으로 제외 |
|---|---|---|---|
| 핵심 흐름 품질 | 희생 | 집중 | 집중 |
| 법적 리스크 | 공고 수집 필요 → 조기 발생 | 공공 API 등 허용된 출처 검토 후 | 없음 |
| "어디에 지원할지 모른다"(브리프 문제 1) 대응 | 조기 대응 | 그 전까지는 방향 전환 조언으로 부분 대응 | 대응 안 함 |
| 비용 | 공고 파싱·임베딩 비용 조기 발생 | 이연 | 없음 |

## 결정
B. 매칭은 M4 이후에 착수한다. 그때까지 아래를 유지한다.
- 설계 문서의 노드 정의(Candidate Retrieval, Reranker)와 스키마 필드(`preferences` 등)는 남겨 둔다.
- 문제 1("어디에 지원할지 모른다")은 진단의 **방향 전환 제안**("이 공고보다 Data Engineer 공고에 근거가 강하다")으로 부분 대응한다.
- 매칭 착수 전에 `docs/data-sources.md`에 출처별 약관 검토를 끝낸다.

## 이유
- 핵심 흐름은 공고 DB 없이 완결되므로, 매칭을 미뤄도 서비스가 성립한다.
- 리스크(법무·비용·평가)가 가장 큰 기능을 핵심이 검증된 뒤로 미루는 것이 1인 개발에 맞는 순서다.

## 결과·트레이드오프 (포기한 것)
- 포트폴리오에서 "추천 시스템" 요소가 늦게 나온다. 대신 핵심 흐름의 평가 체계를 더 깊게 보여 준다.

## 재검토 조건
- 핵심 흐름의 M1~M3 지표가 기준을 충족하고, 허용된 공고 출처가 확보되었을 때 착수한다.
