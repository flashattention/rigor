# ADR-0005: 공고 수집 방식

- 상태: 채택됨 (2026-11-01)
- 날짜: 2026-11-01
- 관련: `docs/brief-review.md` §2, 후속 `docs/data-sources.md`

> 법률 자문이 아니다. "미확인"은 약관 원문을 직접 확인하지 못한 항목이다.

## 배경
핵심 흐름(공고 1개 + 이력서 + GitHub)은 **사용자가 공고를 제공하면 완결**된다. 공고 DB는 확장 기능(매칭)에만 필요하다. 한편 국내에서는 채용정보 무단 크롤링이 부정경쟁행위·데이터베이스제작자 권리 침해로 인정된 판결이 있다(잡코리아 v. 사람인 — 1심 서울중앙지법 2015가합517982, 2심 서울고법 2016나2019365; 최종 결과·금액은 판결문 확인 필요). 따라서 수집 방식은 "얼마나 많이"보다 "어디까지 합법이 확실한가"로 정한다.

## 검토한 선택지

| 기준 | A. 사용자 붙여넣기 | B. 공공 API (워크넷/고용24, data.go.kr) | C. 민간 플랫폼 공식 API | D. 기업 ATS 공개 보드 (Greenhouse·Lever·Ashby 등) | E. 크롤링 |
|---|---|---|---|---|---|
| 합법성 | 높음(사용자 범위 내) | 높음(이용 조건 준수) | 약관 의존 — **미확인** | ATS·기업 약관 의존 — **미확인** | **낮음** (판례) |
| IT 스타트업 커버리지 | 사용자가 원하는 공고 100% | 낮을 것으로 예상(미검증) | 높음 | 해외·일부 국내 스타트업 | 높음 |
| 구조화 품질 | JD Parser 필요 | 필드 일부 구조화 | 구조화 | 구조화 + 본문 | 불안정 |
| 운영 비용 | 없음 | 승인 절차(운영 단계 심의 가능) | 키 발급·제휴 | 기업별 보드 토큰 관리 | 차단 대응 |
| 매칭에 사용 가능 | 사용자 간 공유 시 문제 | O | 약관 따라 | 약관 따라 | X |

## 결정
1. **M1~M3: A만 사용.** 붙여넣은 공고(텍스트 또는 URL에서 사용자가 복사한 텍스트)는 **그 사용자 범위로만 저장**하고, 다른 사용자의 매칭·캐시에 재사용하지 않는다. 서버가 사용자 대신 URL을 가져오지 않는다(크롤링과 경계가 모호해지므로).
2. **M4+ 매칭: B부터 시작**, C·D는 출처별 약관 검토 결과를 `docs/data-sources.md`에 기록하고 허용이 명확한 것만 추가. 저장 시 출처·수집 시각·원문 링크·약관 버전을 기록하고, 마감 공고는 매칭에서 제외.
3. **E는 배제.**

## 이유
1. 핵심 흐름의 법적 리스크를 0에 가깝게 유지하면서 M3까지 실서비스가 가능하다.
2. 사용자 간 공유를 금지하는 이유: 붙여넣은 공고를 모아 다른 사용자에게 보여 주면 사실상 **공고 DB 구축·재배포**가 되어 E와 같은 문제가 생길 수 있다.

## 결과·트레이드오프 (포기한 것)
- 매칭 기능이 M4 이후로 밀린다. "어디에 지원할지 모른다"(브리프 문제 1)는 초기에 직무 방향 전환 조언으로만 부분 대응한다.
- 같은 공고를 여러 사용자가 붙여넣으면 파싱 비용이 중복된다 → 사용자 범위 캐시만 허용(비용 증가 감수).

## 재검토 조건
- 민간 플랫폼과 제휴가 성사될 때(이해상충 정책 ADR 선행 필요).
- B의 커버리지가 IT 직군에서 실측 기준(예: 목표 직무 공고의 30%) 미만이면 C·D 검토 우선순위 상향.

## 승인 기록 (2026-11-01)
